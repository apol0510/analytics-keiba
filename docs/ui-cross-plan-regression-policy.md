# UI修正の全プラン横断ルール

AKの予想画面に関するUI修正は、以下の6経路すべてを対象とする。

## 対象経路

### JRA
- free
- light
- premium

### 南関
- free
- light
- premium

## 禁止事項
- 1ページ・1プランだけを修正して完了扱いする
- 同型UIへ個別CSSを重複追加する
- freeだけ、premiumだけ、JRAだけ、南関だけを確認してPASS判定する
- ユーザーへ6画面すべての実機目視を要求する
- Chromiumの1経路だけでPASS判定する
- URLや実装ファイルを推測したまま修正する
- 共通化できるUIをページ別CSSで場当たり修正する

## 必須事項
- JRA / 南関 × free / light / premium の実URLと実装ファイルを対応表にする
- 共通コンポーネントまたは共通CSSを最優先する
- 6経路すべてをPlaywright等で自動検証する
- ChromiumとWebKitを確認する
- mobileとdesktopを確認する
- アコーディオン開閉前後を確認する
- 横スクロール、幅、余白、高さ再計算を数値検証する
- 全6経路の結果を個別に報告する
- 1経路でも未確認・未改善なら判定Aにしない

## ユーザー目視の扱い
ユーザーのiPhone実機確認は最終補助確認とする。
6経路すべての確認をユーザーへ依頼してはいけない。
Claude側の自動検証で6経路を網羅し、ユーザーには代表画面または問題箇所のみ確認を依頼する。

## 修正方針
優先順位：
1. 共通コンポーネント
2. 共通CSS
3. modifier classによる最小差分
4. 個別ページCSSは最後の手段

## 完了条件
- JRA free / light / premium 全件PASS
- 南関 free / light / premium 全件PASS
- mobile全幅で横スクロールなし
- desktop退行なし
- アコーディオン正常
- build成功
- 対象外データ処理に変更なし
