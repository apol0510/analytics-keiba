# 有料予想の取得方式（1 予想ずつ取得）／ Premium Sanrenpuku のレース選別

> 2026-10-03 MK 確定。正本の要約は `docs/spec.md`「有料予想は 1 予想ずつ取得する」、経緯は `docs/decisions.md` 2026-10-03。
> この文書は Premium / Premium Sanrenpuku の**対象仕様書**（画面・権利・データ・テスト）。

## 1. 原則

| # | 仕様 |
|---|---|
| 1 | 有料予想の「全部見える方式」を廃止し、**1 予想（＝1 レース）ずつ取得**する |
| 2 | **取得前は予想本文を一切出さない**（HTML・JSON・クライアント側の隠し要素にも入れない）。出すのはレース名・発走時刻・距離・頭数などの出走情報だけ |
| 3 | 取得後は「取得済み」。**いつでも再閲覧できる**（予想データの保持期間に依存しない。§4 のスナップショット）|
| 4 | **取得数に上限は無い**（Premium は全レース取得できる。会員の権利は縮小しない）|
| 5 | 本文は**サーバーが「この会員が取得済み」を確認したときだけ**描画する。URL 直打ち・他会員の取得キーでは見られない |

## 2. 商品ごとの表示

| 商品 | 取得単位 | 取得後に出すもの |
|---|---|---|
| **Premium**（**馬単専用**）| レースごと（`premium`）| ①**馬単 通常の買い目**（取込時に確定した `bettingLines.umatan` そのもの）②**馬単 点数を絞った買い目**（§3）③ 印（本命・対抗・単穴）と AI 総合指数 ④ 連下／抑え／評価外 ⑤ **過去走**（全馬・§2-1）。**三連複の買い目は出さない**（Premium Sanrenpuku の商品価値・2026-10-03 MK 確定 v2）|
| **Premium Sanrenpuku** | レースごと（`srp`）| **推奨度（A / B）または見送り判定**・**選別理由**・**通常買い目**・**中心買い目** |

### 2-1. Premium 詳細画面（v2・2026-10-03 MK 確定）

- 構成: レース情報 → 取得済み状態（取得日時）→ 馬単 通常 → 馬単 点数を絞った買い目 → 印と AI 総合指数 → 連下／抑え／評価外 → 過去走 → 取得済み予想への導線
- **無料ページで見られる情報を減らさない**。過去走は無料ページと同じ取り出し方（`pastRaces.js`）で**全馬ぶん**保存・表示する
  - 中央: horseHistories 由来 → 無ければ racebook の近走。新しい順に最大 5 走 ＋「過去走データ」（通算・勝率・連対率・3着内率・条件別・競走成績 10 走）
  - 南関: entries 由来 → 無ければ histories／uma_info／racebook（`getDisplayRecentRacesForNankan`）。新しい順に最大 5 走
- 本文の版 `v`: 1 = 初版（Premium に三連複・過去走なし）／2 = 現行。v1 の保存データは三連複を描画せず、過去走は予想データが残っていれば現行の取り出し方で補う（買い目・印・指数は保存時のまま）
- 見た目はガラスモーフィズム（半透明カード・ぼかし・細い境界線・控えめな光彩）。情報階層と可読性を優先し、ぼかし非対応ブラウザでは不透明背景に落とす。PC は 2 列、900px 以下は 1 列、560px 以下は表の補助列を隠し横スクロールなし
- 認可・取得・URL・SSR・fail closed は変えない（見た目のために権利判定を変えない）

### 2-2. mobile-first とガラスモーフィズムの統一（2026-10-03 MK 追加確定）

- **mobile は PC の縮小版にしない**。最優先は「レースを選ぶ → 予想を取得 → 内容を見る」
  - 一覧: 今月の利用状況はスマホでは一覧の**上の 1 行サマリー**（`AcquisitionUsagePanel variant="mini"`）。最近取得した予想は**一覧の下で折りたたみ**（`variant="side"`・PC では右カラム）。PC の右カラムをそのまま下に積まない
  - 一覧: 装飾の指標ブロック（ai-metrics）はスマホで省き、取得一覧をすぐ出す。日付タブは新しい日付から
  - 詳細（スマホの順）: レース情報 → 取得済み → 馬単 通常 → 馬単 絞り → 本命・対抗・単穴（カード）→ 連下／抑え／評価外（チップ）→ 過去走（馬ごと・走ごとのカード）→ 取得済み予想への導線
- **ガラスを全要素で統一**（`src/styles/acquisitionGlass.css`・`ag-` 接頭辞）: 半透明背景＋`backdrop-filter: blur`＋明るい半透明 border＋内側ハイライト＋淡い glow。背景は濃紺に青（左上）・紫（右上）・シアンの淡い光源。レースカード・買い目・指数・印・過去走・取得済み・CTA・チップまで同じ部品
- **ダーク一辺倒にしない**: CTA は紫〜青のグラデーション、取得済みは green glow、セクションごとに明度差
- **連下／抑え／評価外は「/」区切りの文字列を禁止**。1 頭ずつ独立したチップ（馬番バッジ＋馬名・長い馬名や (外)/(地) でも崩れない・PC は複数列／mobile は 2 列）。色: 本命 赤 / 対抗 アンバー / 単穴 青 / 連下 シアン / 抑え 薄紫 / 評価外 グレー（読める範囲でコントラストを落とす）
- **過去走**: 情報量は落とさない。PC は表、mobile は横長の表を縮めず馬ごとの accordion＋走ごとのカード。全馬の導線を維持
- 完成条件: 375 / 390 / 430px で横スクロールなし・CTA 高さ 44px 以上・長い馬名で崩れない・チップが文字列の塊に見えない・ガラス効果が明確・過去走を省略しない

### 2-3. 活用状況（価値の見せ方）・会場タブ・明るさ・着順の色（2026-10-03 / 10-04 MK 追加確定）

- **目的**: 件数管理ではなく「この価格でこれだけ使える」「継続するほど価値がある」を自然に伝える
- **本日の使用状況**（主役・スマホは一覧の最上部。2026-10-04 に「本日の活用状況」から改称）: `取得したレース / その契約で本日取得できる実レース数 %`（例 12/36レース 33%）
  - 分母は固定値ではなく**その日の実レース数**: 中央のみ契約 = 当日の中央全レース／南関のみ = 当日の南関全レース／Premium = 中央＋南関
  - % は**利用上限ではない**（本日これだけのレースが月額内で利用できる、の指標）。「残り○回」などクレジット制に見える表現は使わない
  - **主訴求は次に取得できる予想**（「次のレースの予想を取得する」→ 最初の未取得レースへ。本日分を取得し終えたら次の開催日）
- **今月の活用状況**（PC 右カラム／スマホは一覧の下）: 取得レース数・利用日数・中央/南関内訳・**1 レースあたりの実質額**（月額 ÷ 取得数）＋「使うほど 1 レースあたりの実質額が下がります」
  - 月額は**定価**で計算（Stripe 月額 ¥4,980・中央版/南関版 ¥2,980・銀行振込 30 日 ¥18,000・年額 ¥49,800 ÷ 12）。特典価格で契約していても実際より安く見せない。買い切り・無料特典・三連複の選別は実質額を出さない（`valueSummary.js`）
  - 取得済みの見返しは機能として残すが、価値訴求の主役にしない（控えめなリンク）
- **ランク／リワード**を入れる場合は次の利用を促す設計（取得数だけでなく利用日数＋継続月数＋取得数）。過去閲覧を主条件にしない（現時点で未導入）
- **会場タブ**: Premium 取得一覧に「すべて（`/predictions/`）／中央競馬／南関東競馬」。日付タブとは別軸
- **明るさ**: ベースのネイビーは維持し、blue / cyan / lavender / soft white の光、半透明の白と淡い青紫の反射、内側ハイライトで軽さと高級感。CTA・取得済み・選択タブ・統計カードまで統一
- **着順の色**: 1着 ゴールド／2着 明るいシルバー・アイスブルー（文字白・縁取り・軽いグロー。灰色にしない）／3着 ブロンズ

### 2-4. /free/・/free-prediction/・/predictions/ の役割と共通デザイン（2026-10-04 MK 確定）

| URL | 役割 | デザイン |
|---|---|---|
| `/free/{jra,nankan}/` | 無料ユーザーが**日常利用**する無料予想（AI 印を見る場所）| 現行の無料専用 UI のまま。Premium 系 UI へ寄せない |
| `/free-prediction/{all,jra,nankan}/` | **Premium の体験プレビュー**（ショールーム）| `/predictions/` と**同一デザインシステム・同一コンポーネント** |
| `/predictions/`・`/premium-prediction/{jra,nankan}/` | Premium 会員が予想を 1 件ずつ取得する**本番利用画面** | 同上 |

- 導線は 3 段階: 無料日常利用（`/free/`）→ Premium 体験（`/free-prediction/`）→ Premium 本利用（`/predictions/`）
- **違いは権限状態と CTA だけ**。日付タブ・会場タブ・レースカード（R・発走・距離・頭数）・余白・タイポ・ガラス・配色・CTA の位置・mobile UI は共通部品（`PremiumRaceBoard` / `AcquisitionRaceList` / `AcquisitionVenueTabs` / `acquisitionGlass.css`）。別 CSS を重複管理しない
- **Preview の一覧**: Premium と同じカード・同じ CTA 位置に「Premiumで予想を取得」（→ `/pricing/`）と注記「この予想を取得するにはPremium」。上部に「Premiumを体験／Premiumではこの画面から気になるレースを1件ずつ取得できます」
- **Preview の詳細**（`/free-prediction/view/?key=`）: Premium 詳細と同じ部品・同じ構成（ただし買い目カードは**「馬単買い目」1 枚だけ**＝2026-10-04 MK 確定。Premium の詳細は通常・絞りの 2 枚）。公開してよい範囲だけ（`freePublicView.js` と同じ: 馬番・馬名・騎手・過去走・上位 4 頭の印 ◎○▲△）。**買い目・AI 総合指数・▲△以外の役割（連下/抑え/評価外の分類）は出さない**（ダミーのモザイクと「Premiumで表示」）。本文スナップショットは作らない
- **Preview で有料本文を漏らさない**: 一覧に買い目・指数・役割を渡さない（`buildRaceListing` のみ）。プレビュー本文は `buildPreviewContent`（買い目・指数・役割を入れない純粋関数）だけから描画
- **CTA の色体系（2026-10-04 MK 確定）**: Premium への導線（「Premiumで予想を取得」「Premiumのプランを見る」「この予想を取得するにはPremium」）は**同じ Premium CTA**（`.ag-cta.ag-cta-premium`）= 明るい紫→青紫のグラデーション・白文字・淡いラベンダーの縁・紫の soft glow、hover で明るく・active で沈む・focus-visible は白い outline。スマホは高さ 52px・全幅。通常の操作（予想を取得する・選択中のタブ）は**青**、取得済みは**緑**で、役割を混同させない
- **タブの色（2026-10-04 MK 確定）**: 会場タブ（すべて／中央競馬／南関東競馬）= **イエロー系のグラデーションのガラス**（選択中は濃い琥珀色の文字・非選択は淡いイエローの文字）。日付タブ = **黄緑の乳白色グラデーションのガラス**（選択中は濃い緑の文字・非選択は淡い黄緑の文字）。CTA の文字はボタンと同系色（Premium = 紫みのあるラベンダー #e9d5ff・通常 = 淡い青）
- **Preview の「Premium なら」パネル（2026-10-04 MK 確定）**: 機能の列挙（「できること」）ではなく、**たくさん使えるメリット**を主役にする。見出し「月額のまま、何レースでも。」＋バッジ「取得回数に上限なし」、使うほど 1 レースあたりがお得・土日の中央も平日の南関も・軸がひと目で・全頭の過去走・取得した予想は手元に残る。買い目の種類（通常・絞り）は強調しない。「取得」という語はそのまま使う（事実のため）
- Premium 側は従来どおり: 同じカードで「予想を取得する」、取得済みは「取得済み／予想を見る」。冪等・他会員非影響・URL 直打ち防止・SSR / fail closed は不変
- `/free-prediction/` は公開ページ（Cookie・会員判定を使わない）→ SSR ＋ CDN 5 分キャッシュ（`/free/` と同じ方式）

- Premium Sanrenpuku は「買い目を少なくする高額商品」ではなく、**三連複で参加すべきレースを AI が選別する上位商品**。
  既存の絞り込み（`generateNarrowSanrenpuku`）は「点数を減らす機能」ではなく**中心買い目**として使う。
- 一覧（取得前）でも推奨度・見送り・選別理由・「今日の上位 3 レース」は見せてよい（**レースの選別結果**であって買い目ではない）。買い目は取得後だけ。
- 見送り判定のレースも取得できる（既存の三連複権利は全レース分。**権利を縮小しない**）。

### 2-5. 取得した予想の結果（マイページ直近 5 件・2026-10-05 MK 確定）

- 直近 5 件に **的中／不的中／結果待ち** を出す。判定は **取得時点の買い目（本文スナップショット）× 結果アーカイブの着順** だけ。推測で「的中」と出さない
- 馬単: 取得した通常＋絞りの買い目のどれかで 1・2 着が当たれば的中。`→` は一方向・`↔` `⇔` `-` は双方向・抑えは含めない（`importResults*.js` の `checkUmatanHit` と同じ）
- 三連複: 取得した通常＋中心のフォーメーションに 1〜3 着の組が含まれれば的中（抑えは 3 列目に含める＝`sanrenpukuBetting` と同じ）
- 払戻はアーカイブにある値だけ出す（馬単=`umatan.payout`／三連複=通常買い目で的中した日の `payout`）。無ければ金額を出さない
- 着順が無い（レース前・取込前）は「結果待ち」。買い目が無い（見送り等）は何も出さない。本文や Redis が読めないときは結果欄ごと出さない（不的中・結果待ちに化けさせない）
- 色は正本 [`GLASS_DESIGN_RULES.md`](./GLASS_DESIGN_RULES.md)（緑=的中・金=払戻・赤=不的中・黄=結果待ち）
- 取得済み予想の画面 `/predictions/view/`: ヘッダー直下に「レース結果」（1〜3 着を金・銀・銅、的中/不的中、払戻=100円あたり、結果待ち）。本文では**当たった買い目の行だけ**を緑にし、その行の着順の馬番を着順色にする（外れた行には何も付けない）。推奨度 A=ローズ／B=琥珀／見送り=青、三連複 中心=金の色付きガラス
- 取得履歴 `/predictions/history/`: 各予想に同じ結果チップ＋先頭に「取得した予想の成績」（的中数／結果が出た件数・的中率・最高払戻＝100円あたり）。分母は結果が出たものだけ。会員ごとに買い方が違うため**払戻合計・回収率は出さない**。レース日ごとにまとめ、右カラムは今月の活用状況だけ（直近 5 件の重複表示をしない）。結果の判定は新しい 60 件まで
- 実装: `src/lib/acquisition/acquiredResults.js`（判定・索引）／`acquisitionServer.loadAcquiredResults`／`AcquisitionUsagePanel`（`results` prop）

## 3. 判定の定義（単一源）

| 項目 | 定義 | 単一源 |
|---|---|---|
| 通常の馬単 | 取込時の `bettingLines.umatan`（無ければ `generateRaceUmatanLines`）。`(抑え…)` は表示しない | `src/lib/acquisition/predictionContent.js` |
| 点数を絞った馬単 | 本命軸、相手を**役割優先（対抗→単穴→連下最上位→連下、同役割は pt 降順）の上位 3 頭**に絞る。向きは通常の 1 行目と同じ（メインレース `→` = 3 点／通常 `↔` = 6 点）。対抗軸の 2 行目は作らない | 同上 `narrowUmatan` |
| 三連複 通常 | `generateNormalSanrenpuku(horses,'本命' / '対抗')` | `src/utils/sanrenpukuBetting.js` |
| 三連複 中心 | `generateNarrowSanrenpuku(horses)` | 同上 |
| 推奨度・見送り | 本命の指数・本命と 2 番手の評価差・頭数・中心買い目の有無から A / B / 見送り。理由は満たした条件の文 | `src/lib/acquisition/sanrenpukuSelection.js` |

- 表示する指数は必ず `getHorseAiIndex`（raw − 1）。理由文に指数の数値は書かない。
- 点数を絞った馬単には「厳選」等の確度を誇張するバッジ・文言を付けない（少点数は的中が難しくリスクが高いため／2026-10-04 MK 確定・`test:acquisition` で検知）。
- 点数を絞った馬単・推奨度は**表示用**。的中判定・アーカイブ（`importResults*`）の対象は従来どおり通常の買い目だけ。
- 【MK 確定仕様・2026-10-06・本番反映は Preview 目視後】実績の購入点数は「少ない買い目＋通常買い目を参照した 2〜6 組」の AI レース別算定（`race.aiBet.points`・`src/lib/results/aiBetPoints.js`・正本 `BET_POINT_LOGIC.md`）。的中は通常買い目・払戻は通常買い目で記録された払戻。**Premium の少ない買い目・通常買い目は一切変えない**。第 3 の買い目は作らない・表示しない。

## 4. データと保存

- 予想キー: `{product}:{cat}:{date}:{venue}:{raceNumber}`（例 `premium:nankan:2026-10-03:funabashi:11`、JRA の会場はコード `TOK` 等）。形式外は拒否。
- 保存は Upstash Redis（本番 schema を増やさない）:
  - 取得履歴 `ak:acq:v1:u:{recordId}`（HASH・field=予想キー・**HSETNX＝最初の取得だけ記録**＝二重取得は冪等）
  - 本文スナップショット `ak:acq:v1:c:{予想キー}:{内容ハッシュ}`（SET NX・内容が同じなら全会員で 1 つ）。
    取得時点の本文を残すので、予想データが SSR から間引かれても（JRA は直近 3 日）再閲覧できる。
- 取得・閲覧の主体は `ak_session` の recordId **1 件だけ**。クライアントから recordId を受け取らない。他会員のキーは読まない。
- Redis が読めない・書けないときは**本文を出さない**（fail closed）。
- rollback: 機能を戻すときは取得履歴を残したまま旧ページへ戻せる（履歴は削除しない）。キーは `ak:acq:v1:*` だけ。
