# 有料予想の取得方式（1 予想ずつ取得）／ Premium Sanrenpuku のレース選別

> 2026-10-03 MK 確定。正本の要約は `docs/spec.md`「有料予想は 1 予想ずつ取得する」、経緯は `docs/decisions.md` 2026-10-03。
> この文書は Premium / Premium Sanrenpuku の**対象仕様書**（画面・権利・データ・テスト）。

## 1. 原則

| # | 仕様 |
|---|---|
| 1 | 有料予想の「全部見える方式」を廃止し、**1 予想（＝1 レース）ずつ取得**する |
| 2 | **取得前は予想本文を一切出さない**（HTML・JSON・クライアント側の隠し要素にも入れない）。出すのはレース名・発走時刻・距離・頭数などの出走情報だけ |
| 3 | 取得後は「取得済み」。**いつでも再閲覧できる**（予想データの保持期間に依存しない。§4 のスナップショット）|
| 4 | **取得数に上限は無い**（Premium は全レース取得できる。会員の権利は縮小しない）|
| 5 | 本文は**サーバーが「この会員が取得済み」を確認したときだけ**描画する。URL 直打ち・他会員の取得キーでは見られない |

## 2. 商品ごとの表示

| 商品 | 取得単位 | 取得後に出すもの |
|---|---|---|
| **Premium**（**馬単専用**）| レースごと（`premium`）| ①**馬単 通常の買い目**（取込時に確定した `bettingLines.umatan` そのもの）②**馬単 点数を絞った買い目**（§3）③ 印（本命・対抗・単穴）と AI 総合指数 ④ 連下／抑え／評価外 ⑤ **過去走**（全馬・§2-1）。**三連複の買い目は出さない**（Premium Sanrenpuku の商品価値・2026-10-03 MK 確定 v2）|
| **Premium Sanrenpuku** | レースごと（`srp`）| **推奨度（A / B）または見送り判定**・**選別理由**・**通常買い目**・**中心買い目** |

### 2-1. Premium 詳細画面（v2・2026-10-03 MK 確定）

- 構成: レース情報 → 取得済み状態（取得日時）→ 馬単 通常 → 馬単 点数を絞った買い目 → 印と AI 総合指数 → 連下／抑え／評価外 → 過去走 → 取得済み予想への導線
- **無料ページで見られる情報を減らさない**。過去走は無料ページと同じ取り出し方（`pastRaces.js`）で**全馬ぶん**保存・表示する
  - 中央: horseHistories 由来 → 無ければ racebook の近走。新しい順に最大 5 走 ＋「過去走データ」（通算・勝率・連対率・3着内率・条件別・競走成績 10 走）
  - 南関: entries 由来 → 無ければ histories／uma_info／racebook（`getDisplayRecentRacesForNankan`）。新しい順に最大 5 走
- 本文の版 `v`: 1 = 初版（Premium に三連複・過去走なし）／2 = 現行。v1 の保存データは三連複を描画せず、過去走は予想データが残っていれば現行の取り出し方で補う（買い目・印・指数は保存時のまま）
- 見た目はガラスモーフィズム（半透明カード・ぼかし・細い境界線・控えめな光彩）。情報階層と可読性を優先し、ぼかし非対応ブラウザでは不透明背景に落とす。PC は 2 列、900px 以下は 1 列、560px 以下は表の補助列を隠し横スクロールなし
- 認可・取得・URL・SSR・fail closed は変えない（見た目のために権利判定を変えない）

### 2-2. mobile-first とガラスモーフィズムの統一（2026-10-03 MK 追加確定）

- **mobile は PC の縮小版にしない**。最優先は「レースを選ぶ → 予想を取得 → 内容を見る」
  - 一覧: 今月の利用状況はスマホでは一覧の**上の 1 行サマリー**（`AcquisitionUsagePanel variant="mini"`）。最近取得した予想は**一覧の下で折りたたみ**（`variant="side"`・PC では右カラム）。PC の右カラムをそのまま下に積まない
  - 一覧: 装飾の指標ブロック（ai-metrics）はスマホで省き、取得一覧をすぐ出す。日付タブは新しい日付から
  - 詳細（スマホの順）: レース情報 → 取得済み → 馬単 通常 → 馬単 絞り → 本命・対抗・単穴（カード）→ 連下／抑え／評価外（チップ）→ 過去走（馬ごと・走ごとのカード）→ 取得済み予想への導線
- **ガラスを全要素で統一**（`src/styles/acquisitionGlass.css`・`ag-` 接頭辞）: 半透明背景＋`backdrop-filter: blur`＋明るい半透明 border＋内側ハイライト＋淡い glow。背景は濃紺に青（左上）・紫（右上）・シアンの淡い光源。レースカード・買い目・指数・印・過去走・取得済み・CTA・チップまで同じ部品
- **ダーク一辺倒にしない**: CTA は紫〜青のグラデーション、取得済みは green glow、セクションごとに明度差
- **連下／抑え／評価外は「/」区切りの文字列を禁止**。1 頭ずつ独立したチップ（馬番バッジ＋馬名・長い馬名や (外)/(地) でも崩れない・PC は複数列／mobile は 2 列）。色: 本命 赤 / 対抗 アンバー / 単穴 青 / 連下 シアン / 抑え 薄紫 / 評価外 グレー（読める範囲でコントラストを落とす）
- **過去走**: 情報量は落とさない。PC は表、mobile は横長の表を縮めず馬ごとの accordion＋走ごとのカード。全馬の導線を維持
- 完成条件: 375 / 390 / 430px で横スクロールなし・CTA 高さ 44px 以上・長い馬名で崩れない・チップが文字列の塊に見えない・ガラス効果が明確・過去走を省略しない

- Premium Sanrenpuku は「買い目を少なくする高額商品」ではなく、**三連複で参加すべきレースを AI が選別する上位商品**。
  既存の絞り込み（`generateNarrowSanrenpuku`）は「点数を減らす機能」ではなく**中心買い目**として使う。
- 一覧（取得前）でも推奨度・見送り・選別理由・「今日の上位 3 レース」は見せてよい（**レースの選別結果**であって買い目ではない）。買い目は取得後だけ。
- 見送り判定のレースも取得できる（既存の三連複権利は全レース分。**権利を縮小しない**）。

## 3. 判定の定義（単一源）

| 項目 | 定義 | 単一源 |
|---|---|---|
| 通常の馬単 | 取込時の `bettingLines.umatan`（無ければ `generateRaceUmatanLines`）。`(抑え…)` は表示しない | `src/lib/acquisition/predictionContent.js` |
| 点数を絞った馬単 | 本命軸、相手を**役割優先（対抗→単穴→連下最上位→連下、同役割は pt 降順）の上位 3 頭**に絞る。向きは通常の 1 行目と同じ（メインレース `→` = 3 点／通常 `↔` = 6 点）。対抗軸の 2 行目は作らない | 同上 `narrowUmatan` |
| 三連複 通常 | `generateNormalSanrenpuku(horses,'本命' / '対抗')` | `src/utils/sanrenpukuBetting.js` |
| 三連複 中心 | `generateNarrowSanrenpuku(horses)` | 同上 |
| 推奨度・見送り | 本命の指数・本命と 2 番手の評価差・頭数・中心買い目の有無から A / B / 見送り。理由は満たした条件の文 | `src/lib/acquisition/sanrenpukuSelection.js` |

- 表示する指数は必ず `getHorseAiIndex`（raw − 1）。理由文に指数の数値は書かない。
- 点数を絞った馬単・推奨度は**表示用**。的中判定・アーカイブ（`importResults*`）の対象は従来どおり通常の買い目だけ。

## 4. データと保存

- 予想キー: `{product}:{cat}:{date}:{venue}:{raceNumber}`（例 `premium:nankan:2026-10-03:funabashi:11`、JRA の会場はコード `TOK` 等）。形式外は拒否。
- 保存は Upstash Redis（本番 schema を増やさない）:
  - 取得履歴 `ak:acq:v1:u:{recordId}`（HASH・field=予想キー・**HSETNX＝最初の取得だけ記録**＝二重取得は冪等）
  - 本文スナップショット `ak:acq:v1:c:{予想キー}:{内容ハッシュ}`（SET NX・内容が同じなら全会員で 1 つ）。
    取得時点の本文を残すので、予想データが SSR から間引かれても（JRA は直近 3 日）再閲覧できる。
- 取得・閲覧の主体は `ak_session` の recordId **1 件だけ**。クライアントから recordId を受け取らない。他会員のキーは読まない。
- Redis が読めない・書けないときは**本文を出さない**（fail closed）。
- rollback: 機能を戻すときは取得履歴を残したまま旧ページへ戻せる（履歴は削除しない）。キーは `ak:acq:v1:*` だけ。

## 5. 画面

| URL | 役割 |
|---|---|
| `/premium-prediction/jra/` ・ `/premium-prediction/nankan/` | Premium の「予想を取得」一覧（日付・会場ごと）。各レースに取得ボタン／取得済み＋「予想を見る」。右に今月の利用状況と取得済み（直近 5 件）|
| `/premium-sanrenpuku-jra/` ・ `/premium-sanrenpuku/` | Premium Sanrenpuku の「本日の三連複 推奨レース」（推奨 A/B・上位 3・見送り候補）と全レースの判定一覧 |
| `/predictions/view/?key=…` | 取得済みの予想本文（取得していなければ本文なし・一覧へ戻す）|
| `/predictions/history/` | 取得済みの予想（すべて）|
| `POST /api/predictions/acquire` | 取得（フォーム送信・303 で本文へ）。同一オリジン以外は拒否 |
| `/dashboard/` | 今月の取得数・利用日数・中央/南関別・最近取得した予想 |

- 既存の会員状態・日次分析・三連複/Premium Plus の導線・問い合わせは各ページにそのまま残す。
- Light・無料ページは対象外（変更しない）。

## 6. CTA（三連複関連・全面統一）

- 「点数を絞る」「少点数」「6〜9点」中心の訴求をやめ、**「今日、三連複で狙うべきレースを AI が選別」「買うレースを選ぶ」「推奨レースの予想を取得する」**へ統一。
- 送信済みのメール文面は変えない（version を上げると全員へ再送になる）。未送信の文面だけ書き直す。送信済みで旧訴求のものは再利用前に書き直す（guard テストが検査）。

## 7. 変えないもの

- 既存 Premium Sanrenpuku 購入者の権利（`LifetimeSanrenpuku`・`canViewSanrenpuku`）。
- Premium Plus の eligibility / override / phase / route / CTA / purchase gate（別概念）。
- 料金・販売条件。的中判定・アーカイブ。

## 8. テスト（`npm run test:acquisition` → `check:safety`）

取得前は本文非表示／取得後のみ表示／二重取得は冪等／URL 直打ちで未取得本文を見られない／他会員の取得状態に影響しない／権限外は取得不可／
Premium 馬単は通常＋絞り／Premium 三連複は通常／Premium Sanrenpuku は推奨・見送り・通常・中心・理由／CTA 表示条件と商品差分／
既存購入者権利の維持／Premium Plus の既存 route・eligibility を壊さない。
