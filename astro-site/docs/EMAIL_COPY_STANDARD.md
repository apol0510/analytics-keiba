# 販促メール コピー品質基準（正本 / 2026-09-15 MK 確定）

AK から送る DRM・販促メールは、**単なる「期限・価格・リンクの通知文」で終わらせない**。

受信者が次の順に自然に理解できる状態を、1 通ごとの完成条件とする。

> **何の案内なのか → 自分に関係があるのか → 何が得られるのか
> → なぜ今検討するのか → 次に何をすればよいのか**

## なぜ確定したか（2026-09-15）

三連複割引メール（`campaign-discount-premium`）が

- 「9月23日まで」
- 「10,000円OFF」
- 「マイページから申し込み」

という**事実の列挙**しか伝えておらず、受信者が「なぜ三連複を追加するのか」
「自分にどんな価値があるのか」を理解して行動できる内容になっていなかった。

今回の 1 通だけの問題ではない。**同様に味気ない既存の DRM・割引・アップセル・
再募集メールすべて**を対象とする。

## 適用範囲

| 対象 | 扱い |
|---|---|
| DRM シーケンス（無料登録者育成 / Light → Premium / Premium → 三連複）| **対象** |
| 割引・再募集・アップセル・カムバック | **対象** |
| 配信経路の疎通確認（`marketing-canary`）| 対象外（販促メールではない）|
| 取引メール（入金確認・マジックリンク等）| 対象外（本基準は販促メール専用）|

## 🚨 触ってはいけない前提（コピー改善で変えないもの）

コピーの改善は**文章だけ**を対象とする。次は 1 つも変えない。
必要な場合は「**仕様変更**」として別途 MK へ報告し、承認を得るまで実施しない。

- 配信対象 / 配信順序 / 配信時刻 / 間隔（`delayDays`）
- `campaignId` / `version`
- 自動化条件 / eligibility / `audienceRule` / `stopOnPurchase` / `autoStart` / `responseRoutes`
- 購入条件 / 会員権限
- 価格 / 割引額 / 期限 / 商品内容
- unsubscribe・List-Unsubscribe 等の法務上必要な要素（送信基盤が自動付与する）

## 🔒 送信済み Step は 1 バイトも変更しない（ルール (C)）

`campaignCatalog.js` のルール (C) は本基準に**優先する**。

- `DeliveryKey = campaignId × version × step × 受信者`。本文ハッシュを含まない
- したがって **送信済み Step の文面を直しても、既に受け取った方へ修正版は届かない**
- `version` を上げれば届くが、**step1 から全員へ配り直し**になる
  （`campaign-discount-free` の 15,509 名を含む再送＝配信対象・配信回数の仕様変更）

よって、**改稿してよいのは未送信 Step だけ**。送信済み・稼働中のものは
「改稿不能」として一覧に残し、無理に触らない。

> 稼働中のキャンペーン（期間内で tick が 10 分ごとに回っているもの）は、
> 作業中に任意の Step が送信され得るため、**全 Step を改稿不能として扱う**。

## 制作基準（7 項目）

### 1. 冒頭で受信者との関係を作る

いきなり期限だけを書かない。「現在 Premium をご利用中の方へ」のように、
**なぜこの案内が届いたのか**が分かるようにする。

- 機械判定: 本文の最初の 2 行に `RELATION_MARKERS` のいずれかを含む

### 2. 商品の価値を短く伝える

値引き額だけではなく「**何を追加できる商品なのか**」を説明する。

- ⚠️ repo にない効果・成績・保証・誇張表現は**絶対に創作しない**
- 実績数値の手書きは禁止（`HARDCODED_STAT`）。実データのページへ誘導する
- 機械判定: 本文 `MIN_BODY_CHARS` 以上・`MIN_BODY_LINES` 行以上 /
  特典欄（`benefitTitle` + `benefitItems` 2〜4 件）を持つ

### 3. 既存契約を否定しない

- 現在のプランはそのまま利用できる、と明示する
- 追加商品は「必要な人だけ申し込めばよい」と書く
- 無理な煽り・不安喚起はしない（`FORBIDDEN_PHRASES`）

### 4. 割引理由・期限を明快にする

**正本の数値・日付を絶対に変更しない。**

- 価格・割引額・期限は `campaignOffers.js` / `promotionOfferCatalog.js` /
  `CAMPAIGN_WINDOW` から**導出**する
- ⚠️ メール本文へ金額・日付を**書き写さない**。書き写すとサイトの価格を直したときに
  メールだけ古い金額のまま残り「案内した額と請求額が違う」事故になる

### 5. CTA 直前に「押す理由」がある

ただ「ログインする」ではなく、**何を確認できるか**が分かるコピーにする。

- 例: 「三連複の内容と割引価格を確認する」
- **実際の遷移先・権限・表示条件と必ず一致させる**
- 機械判定: `VAGUE_CTA_LABELS`（こちら / 詳細 / ログイン / サイトを見る 等）単体を禁止 /
  `ctaNote` 必須 / 会員限定ページを権限の無い相手の CTA にしない /
  公開導線の一覧（`PUBLIC_CTA_PATHS`）に無いパスを推測で作らない

#### ⚠️ `/free/` と `/free-prediction/` を取り違えない（2026-09-15 レビューで論点化）

**どちらも現役の別ページで、片方が他方の旧 URL ではない。**

| パス | 中身 | 状態 |
|---|---|---|
| `/free-prediction/{nankan,jra}/` | **有料版プレビュー**。買い目・AI総合指数・役割・不要馬まで出る | nav 掲載・noindex なし・リダイレクトなし |
| `/free/{nankan,jra}/` | **無料コンテンツ第 2 層**（レースの見どころ）。**買い目 / pt / AI総合指数 / 役割 / 特徴量は出さない** | nav 掲載・noindex 解除済み（2026-08-20）・URL は**仮** |

根拠: `src/pages/free/{nankan,jra}.astro` の冒頭に
「`/free-prediction/` の役割（有料版プレビュー）は変更しない。**ここは別ページ**」と明記され、
`/free/` 自身が `/free-prediction/` を「有料版プレビュー」として案内している
（`RaceViewpointsBoard` にも「買い目は有料版で」の CTA がある）。

⚠️ **`/free-prediction/` を「旧 URL」として `/free/` へ置き換えてはいけない。**
買い目や指数を約束した本文を `/free/` へ送ると、**約束したものが無いページに着地**する。

#### ⚠️ `/free-prediction/` でも買い目・AI総合指数・全頭の役割は見られない

**`/free-prediction/` は「有料版のプレビュー」であって「無料予想」ではない**
（2026-08-20 に MK が位置づけを変更）。ページ自身が最上部で
「**AI予測買い目・AI総合指数・累積スコア・役割**は伏せてあり、有料版で公開しています」
と表示している。

無料へ渡してよい範囲の単一源は `src/lib/freePublicView.js` の `buildFreePublicRows()`。

| 無料で見られる | 有料限定（DTO に入れない）|
|---|---|
| 馬番 / 馬名 / 騎手 / 厩舎 / 斤量 / 枠 / 父 / 性齢 / 過去走 / 通算成績 | `pt`（累積スコア）|
| 印 **◎本命 / ○対抗 / ▲単穴 / △連下最上位（上位 4 頭のみ）** | AI総合指数 |
| レース詳細（距離 / 頭数 / 発走時刻）| 特徴量重要度・評価ポイント |
| | **▲単穴 / △連下 / 抑え / 不要馬 の役割** |
| | **買い目**（誰にも解放しない）|

⚠️ したがって「全頭の役割」「AI総合指数」「メインレースの買い目」を
**無料で見られるもの**として案内してはいけない。
**買い目が実際に公開されているのは `/results-showcase/{nankan,jra}/`**
（有料版で配信した前日のメインレース 5 点を、結果と並べて公開している）。

#### 機械判定: 着地先ごとの公開範囲

`LANDING_PAGE_HIDDEN_TERMS` が**着地先ごとに「そこでは見られないもの」**を持ち、
`promise_not_on_landing_page` が突き合わせる。

判定する面は **CTA ラベル / CTA 補足 / 特典欄**（＝「押した先で何が得られるか」を書く面）
**だけ**。本文の散文は商品説明として着地先に無いものへ触れることがあり
（例: Light の範囲を説明しながら `/pricing/` へ送る）、そこまで見ると誤検知になるため
**あえて見ない**。本文の正確さは人のレビューで見る。

### 6. 文章にメリハリをつける

**見出し → 2〜3 行の本文 → 商品価値 → オファー → CTA** の順で読みやすくする。
同じ情報を何度も繰り返さない。

- 機械判定: `preheader` が本文の複製でない / 件名の実語が `MIN_SUBJECT_CORE_CHARS` 以上 /
  件名・本文が他 Step と同一でない（`validateSequence` が既に検査）

### 7. 過度に広告臭くしない

KEIBA Analytics として「煽る営業メール」ではなく
**「会員に必要な情報を、価値まで分かる形で案内する」**トーンを基本とする。

- 顧客向けの文面に**内部運用の語を出さない**（`INTERNAL_AFFAIRS_PHRASES`）。
  「内容と料金はプランのページが**正本**です。メールには書いていません。」は
  運営側の都合であり、受信者には意味が無い

## ファネル上の役割（1 通ごとに目的を持たせる）

同じ文章を使い回さない。「**この 1 通は何のために送るのか**」を明確にする。

```
無料登録者 ──（主軸）──→ Premium
    │                        │
    └──→ Light ─────────────┘        Premium ──→ 三連複（次段アップセル）
```

| campaign | ファネル上の役割 |
|---|---|
| `free-signup-onboarding` | **主軸の入口**。無料登録者に無料の中身を使ってもらい、Premium まで案内する |
| `light-to-premium-sequence` | Light ご利用中の方へ、見られる範囲を広げる選択肢を示す |
| `sanrenpuku-upsell-sequence` | Premium ご利用中の方へ、**次段**として三連複（買い切り）を案内する |
| `campaign-discount-*` | 期間限定の割引案内（区分ごとに案内する商品が違う）|
| `light-trial-*` | Light 無料体験のコホート専用（体験中 6 通 / 終了後 18 通）|

## 🔴 各シーケンスの「最初の接点」は最重要メール

MK 確定（2026-09-15）:

> 今後まだ送られていない各シーケンスの最初の接点は**最重要メール**として扱い、
> 事務通知ではなく「**続きを読みたくなる入口**」まで品質基準に含める。

最初の接点で満たすこと:

1. なぜこのメールが届いたのかが 1 行目で分かる
2. これから何を受け取れるのか（このシーケンスの約束）が分かる
3. **今日すぐ確認できるもの**が 1 つある（次の接点を待たせない）
4. 押した先で何が見られるかが CTA で分かる

### adopt 方式（なぜ全 campaign に課さないか）

ルール (C) により**送信済みの文面は直せない**。基準を全体へ課すと
「直せないのに CI が落ちる」か「凍結を骨抜きにする」かの二択になる。

そこで基準に適合させた campaign を `COPY_STANDARD_ADOPTED` に登録し、
**登録済みのものだけ**を検査する。対象外は `COPY_STANDARD_NOT_ADOPTED` に
**理由つきで**必ず記録する（理由の無い除外はテストが落とす）。

⚠️ **「落ちるから外す」は禁止**。外してよいのは
送信済み・稼働中で書き換えられないものと、別任務が所有しているものだけ。
